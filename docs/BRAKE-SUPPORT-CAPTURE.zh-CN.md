# L2 刹车支撑自动记录版

版本：`1.2.0-preview.4-griploss.3-brakeprobe.1`，2026-10-25。

**行为基线是已固定的 `1.2.0-preview.4-griploss.3`，不是 `l2.1`。** 常态 L2 恢复 `[3,4,4,5,5,6,6,7,7,8]`；ABS/抱死、R2、TC、换挡、轮胎拖拽和左右路肩全部沿用 `.3`。本版先定位支撑变轻的发生条件，没有猜改一组新力度或 ABS 波形，也不表示问题已经解决。

## 操作

1. 完整解压到新目录，保留旧 `.3` 和 `l2.1`。如需沿用个人设置，将实际使用程序旁的 settings、lights、gyro 和存在时的 gyro-calibration JSON 复制到新目录；原文件不改动。
2. 先打开本版普通程序，在自定义模式下确认 **L2 阻力 50、ABS 脉冲 50**。其他参数可以使用平常配置。然后退出普通程序。
3. 双击程序旁的 **`Start Brake Capture.cmd`**。它启用记录模式，不会擅自修改任何保存参数。
4. 进入 ACC，游戏 ABS 开启，正常行驶并完成几次刹车，包含 ABS 介入即可；无需反复切换版本，也无需分辨细微轻重。
5. 回到记录窗口，按 **Ctrl+C** 结束，等出现报告已保存的提示再关窗口。

程序旁 `BrakeSupportRecords/日期时间-短编号/` 自动生成：

- `brake-support.csv`：时间轴、游戏刹车/ABS、同设备物理 L2/R2 原始字节、原始值新鲜度、两侧最终反馈命令、L2 原始基础曲线和 HID 写入状态。
- `summary.json`：自动统计及证据是否充分。
- `分析摘要.zh-CN.md`：可直接阅读的中文结论和不足说明。

把该次日期时间目录保留，后续分析直接使用其中数据。记录结束不需要手动标记“哪一次变轻”。

## 分析能确认什么

- 在有效制动时，L2 是否进入 15 Hz ABS 脉冲模式，以及请求该模式的时间段。
- 该模式切换是否伴随成功 HID 写入，还是没有设备、写入失败或 dry-run。
- 原始 L2 是否接近归一化后段，及基础十区命令如何设置。
- 软件 ABS 提示是否关闭、是否没有采到 ABS、原始输入是否失效、是否出现记录间断或丢弃。

软件 ABS 提示为 0 时，游戏 ABS 的介入不会让插件发送 ABS 脉冲；报告会明确说明不能据此解释基础阻力的轻感。

**手柄没有实际反力传感器。** 原始 0–255 是模拟位置，归一化的十个名义区间未经机械角标定；不同模式的“阻力档”和“振动振幅”不能直接相减当成实际力差。HID 写入成功也不证明执行器达到了某个力量。本版定位软件路径，不声称测量了手指反力。

## 实现范围与回退

仅显式 `--capture-brake` 才创建有界记录缓冲和后台写文件线程。原始位置复用已有 USB 输入线程，正常反馈的采样频率、输出判据和 HID 心跳不变；普通打开程序不启用这些诊断资源。记录最终帧及真实写入决策，常规样本约 50 Hz、模式切换和失败等关键事件单独保留。

诊断存储失败会报告记录不完整，不应改变正常反馈。退出会清空反馈并刷新记录；若记录不完整，不能宣称完整捕获了每次介入。

回退直接运行原 `.3`。其独立归档在 `archive/stable-grip-v1.2.0-preview.4-griploss.3-20261025/`；本轮未修改原归档，也未覆盖 `l2.1` 测试包和源码记录。

离线验证、源码差分和包校验保存在 `artifacts/brake-support-preview4-20261025/`。本轮未启动用户的游戏或操作实际手柄；实机记录需要上述正常刹车过程。
