# 一次启动扳机确认：1.1.0-preview.6

用户希望恢复打开软件时能感知扳机输出的体验。preview.5 新增明确、受控的一次启动动作，
不通过接受旧遥测来恢复它，也不声称能完全复现旧版本某次启动的声音。
旧版响声的具体物理来源仍未通过实机同步记录确认。

用户实测 preview.5 的启动声响较轻，preview.6 将独立启动动作的曲线替换为正式版
v1.0.1 的正常基础阻力曲线，并按当前设置缩放；不修改正常驾驶反馈引擎或启动状态机。

## 行为

- 等待首次 ACC 进程探测完成，并且成功打开手柄后，才允许考虑启动动作。
- 若 ACC 已运行，或已有有效游戏反馈，则消费并跳过该动作；退出 ACC 后不会补播。
- ACC 尚未运行时，L2/R2 建立分区阻力约 120 ms，然后恢复关闭。
- 默认 L2 曲线为 `[3,4,4,5,5,6,6,7,7,8]`，R2 为 `[2,2,2,3,3,3,4,4,5,5]`，与正式版正常基础阻力一致。
- 不使用握把震动电机。按用户该侧基础阻力比例缩放，沿用现有 0–100 设置对应的 0–1.35 比例；某侧设为 0，该侧不动作。硬件分区强度仍限制为 1–8，非有限比例关闭对应侧。
- 脉冲期间关闭该侧基础阻力会立即关闭该侧；该侧在本次动作内也不再启用。第一次动作已消费，不因以后启用设置而再次执行。
- 每个软件进程最多一次。状态保存在进程共享实例，而不是每次创建的运行时/手柄对象中。
- 设备尚未打开的重试不消费机会；但一旦准备首个动作就消费，即使首次写入失败也不因重连重试。
- 拔线、写失败或运行时退出取消动作；原有 finally/Dispose 路径继续尽力发送 Off。

这能确认手柄输出路径有响应，不能证明游戏遥测已工作。实际机械声、力度和释放感觉需要实机确认。
120 ms 是状态机的目标时长，真实设备写入仍受 Windows 调度和原有 HID I/O 影响。

## 与原修复、正常反馈的关系

`AccProcessMonitor`、`AccTelemetrySession`、physics 读取、反馈快照与原有超时保持原样。
`FeedbackRuntime` 在 preview.5 增加首次进程探测已完成标记及启动动作接入，不发布假遥测，不改变 ACC 已检测/驾驶反馈生效的判定；preview.6 保持该接入不变。

动作通过原有唯一输出线程和原有设备句柄发送，不创建第二个 HID 写入线程、不调用阻塞睡眠。
开始动作和结束动作作为帧变化发送，持续期间沿用正常心跳。
新鲜游戏遥测到来即交给原反馈帧；不修改 `CompetitionFeedbackEngine`、震动混合、扳机曲线或校准参数。
输出写入失败后不会再执行启动动作；退出时原有清除机制仍然有效。

dry-run 不执行启动确认、不打开实体手柄、不创建虚拟设备，原无游戏检查仍要求始终没有游戏反馈。

## 验证

自动检查覆盖首次探测等待、120 ms 边界、USB/BT 编码、握把电机为零、无手柄重试、
模拟写失败后的取消与重连、运行时取消后复用状态、ACC 已运行跳过、游戏反馈立即接管、
单侧关闭/双侧关闭、强度上限、动作中关闭设置、延迟调度不续期、异常后的取消。
新增默认曲线与正式版基准核对、全部 101 档设置与现有引擎静态基础阻力及 USB/BT 报告一致性、
自定义增强不再被限制为默认力度、异常比例限制。
失败场景使用状态机和内存中的报告，不假称测试了真实 WriteFile 失败或硬件拔插。

实测建议：

1. ACC 关闭、手柄已连：启动软件，动作最多一次，之后释放并等待 ACC。
2. 软件先开、之后连手柄：首次连接一次，随后拔插不重播。
3. ACC 已开或已驾驶：启动软件，跳过独立确认，正常反馈工作。
4. 关闭某侧基础阻力：该侧不执行启动动作。
5. 启动后立即关闭软件、连接失败后重新检查：无残留阻力、无重复动作。

preview.4 已获用户实机反馈“一切正常”；preview.5 便携包也保留。
本版只调整启动力度，需要独立验收启动声响、阻力与释放，不承诺声音与旧版完全一致。
